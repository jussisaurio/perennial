# Perennial — design notes

Perennial is a spaced-repetition app for going from zero to fluent in a language, in
5–10 minutes a day. It takes Anki's core idea (retrieval practice, scheduled
by a memory model) and drops most of what grew around it.

## What's wrong with Anki (and what we do instead)

| Anki problem | Source of pain | Perennial |
|---|---|---|
| **Backlog after missed days.** A wall of "437 due" after a week off makes people quit. | Due-count queue. You "owe" the app reviews. | **Time-boxed sessions.** You pick "7 minutes"; the app spends them on the highest-value items. There is no due count. Overdue items are sorted so the cheapest saves come first, and new words slow down by themselves when there's a backlog. |
| **Boring, grindy reviews.** The same static card 40 times. People memorize the card layout, not the word. | One card = one fixed front/back. | **Memory is per word × skill, not per card.** Each review shows a *different* example sentence for the word (generated by an LLM and cached). Exercises rotate between reading, listening and typing. |
| **Card creation friction.** Note types, HTML templates, fields, finding sentences, recording audio. | Anki is a generic flashcard engine. Language learning is bolted on through add-ons. | **No card creation for the common case.** Pick a language, and the course is built from a real frequency list (OpenSubtitles). An LLM writes graded (i+1) sentences that use words you already know. Or paste any text and tap the words you don't know. Audio comes from the browser's speech synthesis. |
| **Recognition-only decks.** Research (Nakata) shows receptive retrieval mostly builds receptive knowledge. | Default "Basic" note type is L2→L1. | **Three skills per word:** *read* (L2 sentence → meaning), *listen* (audio only → meaning), *write* (L1 meaning + cloze → type the word). Writing unlocks once reading is stable. Each skill has its own memory state. |
| **SM-2 and "ease hell".** Pressing Again repeatedly locks ease at 130%. Learning steps, graduating intervals and easy bonuses confuse people. | 1987 algorithm, with options layered on for 20 years. | **FSRS-6 only.** One setting: desired retention. No learning steps — FSRS models same-day reviews itself. |
| **4 grading buttons.** Users press Hard when they actually forgot, which breaks FSRS. | | **2 buttons: Forgot / Got it.** Typed exercises are graded automatically. |
| **Too many options.** Presets, deck hierarchy, filtered decks, burying toggles, gather/sort orders. | | **One course per language. One setting (minutes per day).** Siblings are never shown in the same session. |
| **Sync: forced one-way "full sync", media that won't sync, last-writer-wins on whole objects.** | Schema-level change counter. Mutable card state is synced as rows. | **Event-sourced sync.** Reviews are an append-only log, so they merge without conflict, and scheduling state is *recomputed* from the log. Content edits are per-field last-writer-wins with hybrid logical clocks. There is no "full sync". |
| **Dated Qt UI, AnkiMobile costs $25, AnkiDroid differs.** | Three separate clients. | **One PWA.** It works offline and installs on phone and desktop. |
| **No sense of progress.** Stats are dense graphs. | | **"You know ~1,240 words ≈ 82% of everyday speech."** Coverage is computed from the frequency list. |

## Research we lean on

- **FSRS-6** (open-spaced-repetition). Its DSR model beats SM-2 by a wide margin
  on the srs-benchmark. Formulas are in `src/core/fsrs.ts`.
- **Frequency-first vocabulary.** A small number of words covers most running
  text: the top ~1,000 lemmas cover ~80–85% of spoken text, and ~3,000 cover
  ~90–95%.
- **Retrieval direction matters** (Nakata 2011, 2016). Productive and receptive
  practice build different knowledge, so we train both.
- **Context over isolated words.** We always show the word in a sentence and
  vary the sentence (against the "static card" problem).
- **Comprehensible input / i+1.** LLM sentences are constrained to the
  learner's known words plus the target word.
- **Desirable difficulty.** Typed recall beats recognition for long-term
  retention. Interleave skills rather than blocking them.
- **Habit formation** (Lally 2010). A small, fixed daily dose with no
  punishment for missed days. No streak guilt.

## Architecture

```
web/ (Vite + React + TS PWA)
  core/      pure, tested logic: FSRS, session planner, answer checking, HLC, coverage
  db/        Dexie (IndexedDB) + op log
  ai/        provider-agnostic LLM client (OpenAI-compatible + Anthropic)
  content/   frequency lists, tokenizer, course builder, text mining
  ui/        screens
server/ (Bun + bun:sqlite)
  POST /sync — push ops, pull ops since cursor. Namespaced by sync key.
```

### Data model

- `Lexeme` — a word/lemma in a course: `lemma`, `gloss`, `pos`, `rank`,
  `forms[]`, `notes`.
- `Example` — a sentence for a lexeme: `text`, `translation`, `cloze`
  (the surface form in the sentence), `source` (`llm` | `mined` | `import`).
- `Review` — immutable: `{itemId, skill, grade, ts, durationMs}`. This is the
  source of truth for scheduling.
- `MemoryState` — *derived* cache: `{itemId, skill, S, D, lastTs, due}`.
  It is never synced. It's rebuilt by replaying reviews.

### Sync

Every local mutation writes a row and an op `{id, hlc, table, rowId, patch}`.
The client pushes unsent ops and pulls ops after its cursor. The server stores
ops in arrival order with an auto-increment sequence. Applying an op:

- `reviews` — insert if new (ids are unique; append-only).
- other tables — per-field last-writer-wins by HLC.

Identity is a random **sync key** shown as a code. Enter it on another device to
link the two. There are no accounts.

### AI

`ai/llm.ts` speaks two dialects: OpenAI chat completions (OpenAI, OpenRouter,
Groq, Together, Ollama, LM Studio…) and Anthropic messages. The user supplies a
base URL, model and key. All prompts request JSON, and responses are validated.

## The garden

Progress is shown as a garden, not as streaks or points. Each word has its own plant, generated from a seed (the word itself). The plant grows with memory stability, flowers once the word is known, and leans a little when recall drops below 90%. Nothing ever dies.

- **Small garden (Today):** an SVG strip of the plants.
- **Walk-in garden (`#/garden`):** a retro 3D world in `web/src/garden/`.
  - `world.ts` has the pure layout: raised beds per kind of word, collision, viewpoints.
  - `textures.ts` draws pixel-art textures procedurally and rasterises the SVG plants into atlases.
  - `scene.ts` is the three.js scene. It renders billboard sprites into a low-resolution framebuffer, which CSS scales up with `image-rendering: pixelated`.
  - The scene is a snapshot taken when the garden opens.
  - three.js loads only on this route.

## Not yet / later

- AnkiConnect-compatible local API, so Yomitan/asbplayer can mine into Perennial.
- FSRS parameter optimization from your own review log. Default parameters are
  used until then.
- Speech recognition for speaking practice.
- FSRS-7 (fractional intervals). We already store ms timestamps.
